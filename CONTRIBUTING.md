# Contribution

## Branch naming

- `feature/prenom-ticket-xxx`
- `fix/prenom-ticket-xxx`
- `docs/prenom-documentation`

## Commit convention

- `feat:` nouvelle analyse
- `fix:` correction
- `docs:` documentation
- `refactor:` amélioration SQL sans changement de résultat
- `test:` contrôle de qualité

## Pull Request

Une PR doit contenir :
- objectif
- ticket
- tables utilisées
- résultat
- captures éventuelles
- limites
- recommandations

## Revue

Le reviewer vérifie :
- lisibilité
- exactitude
- performance
- cohérence métier
- absence de secrets
- documentation
